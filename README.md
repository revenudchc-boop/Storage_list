# خادم الأرشيف المحلي — النسخة 2.0

## التشغيل
1. انسخ كل الملفات إلى مجلد الخادم (بجانب بعضها) وتأكد من تثبيت Node.js 18 أو أحدث.
2. شغّل `start-server.bat`. أول مرة ينشئ ملف `.env` من `.env.example` ويفتحه: راجع المسارات ثم أعد التشغيل.
3. ملفات الواجهة (`index.html`, `auth.js`, `local-server.js`, `config.js`, `archive.js`, `script.js`) تُنسخ إلى مجلد التطبيق على الـ NAS (`APP_PATH`). **لا تضع `users.json` ولا `.env` ولا `server.js` هناك.**
4. عناوين الخادم المحتملة تُعدَّل في `config.js` فقط.

## ما الذي تغيّر
| المشكلة | الحل |
|---|---|
| كلمات المرور نصية | PBKDF2-SHA256 (150 ألف دورة) مع ملح. الملف الجاهز `users.json` محوَّل مسبقاً وكلمات المرور الحالية تعمل كما هي |
| مفتاح API ظاهر في المتصفح وفي الروابط | حُذف. الدخول يُنتج توكن جلسة (8 ساعات)، والتحميل بروابط موقّعة تنتهي بعد ساعتين |
| صلاحيات الخطوط في المتصفح فقط | الخادم يفلتر القائمة والتحميل حسب `lineIds` (الخط يُستخرج من اسم الملف `Ship_Line_Date`)؛ الرفع والحذف للمدير فقط |
| تجاوز المسار (`..`) | `safeResolve` يتحقق أن المسار النهائي داخل مجلد الأرشيف في الرفع والتحميل والحذف |
| الملفات الحساسة قد تُخدَّم بـ `express.static` | قائمة حظر لـ `users.json` و`.env` و`server.js` و`package.json` و`.bat` |
| CORS مفتوح | الشبكة الداخلية + ما تضعه في `ALLOWED_ORIGINS` فقط |
| بيانات NAS في الكود وحقن أوامر في `net use` | في `.env`، ويُنفَّذ الأمر بدون shell |
| رفع base64 داخل JSON | `multipart` (أخف 33%) + فحص توقيع الملف + كتابة ذرّية |
| بطء القائمة | تخزين مؤقت 15 ثانية (يُمسح عند الرفع/الحذف) وقراءة متوازية محدودة |
| أسماء الملفات العربية في التحميل | `filename*=UTF-8''` |
| رفع `_info.json` كان يُرفض بصمت | مسموح الآن |
| فحص الخادم 3 ثوانٍ × كل عنوان بالتتابع | فحص متوازٍ |
| محاولات الدخول في المتصفح | في الخادم (بالمستخدم والـ IP) + سجل تدقيق `data/audit.log` |
| `cached_users` (كلمات المرور) في localStorage | حُذف، والجلسة تنتهي وتُحفظ في sessionStorage (أو localStorage عند "تذكرني") |
| حقن HTML في شريط المستخدم | تهريب القيم |

## خطوات لازمة عليك
- **غيّر كلمات المرور الحالية** (`admin123` وغيرها). كانت ظاهرة نصاً، ويجب اعتبارها مكشوفة. ولّد الجديدة بـ `node tools/hash-password.js "كلمة_المرور"` وضعها في `users.json`.
- **ارفع `users.json` الجديد إلى GitHub** إن كنت تستخدم الدخول عبر GitHub أيضاً (وإلا سيرفض الدخول لأن النص العادي لم يعد مقبولاً). الأفضل جعل المستودع خاصاً.
- ضع كلمة مرور الـ NAS (إن وجدت) في `.env`.
- لتفعيل HTTPS ضع `TLS_CERT` و`TLS_KEY`. بدونه تنتقل كلمة المرور نصاً على الشبكة الداخلية، والتشفير المحلي في المتصفح (للدخول عبر GitHub) لا يعمل على `http://` غير localhost.
- لتشغيله كخدمة Windows: `npm i -g pm2 && pm2 start server.js --name archive && pm2 save` (أو NSSM). و`backup-archive.bat` للنسخ الاحتياطي اليومي عبر Task Scheduler.
- اختبار الأجزاء الأمنية: `npm test`.

## لم يُعدَّل
`script.js` و`archive.js` (لم يُمسّا؛ فيهما مئات استخدامات `innerHTML` وبناء `onclick` من أسماء الملفات، يحتاج مراجعة مستقلة)، و`github_token` المحفوظ في المتصفح، و`settings.json`/`copy.json`.

## الإصدار 3.0: مظهر احترافي ولوحة مؤشرات من المصدرين
- `dashboard.css`: مظهر جديد لكل التطبيق (الهيدر، البطاقات، الجداول، الأزرار، الحقول، شاشة الدخول) فوق أنماط `index.html` دون تغيير أي وظيفة.
- `dashboard.js`: قائمة جانبية عائمة (لوحة المؤشرات، التقارير، الأرشيف، المستخدم) تضغط الأزرار الأصلية نفسها فلا يتأثر `script.js`.
- اللوحة تجلب البيانات من **الخادم المحلي** ومن **GitHub** (`archive/archive_index.json` بلا Token وبلا حد طلبات) وتدمجهما، ويعمل الأرشيف إن توفر أحد المصدرين فقط.
- تعرض: الملفات والسفن والحجم، آخر سفينة بملفاتها، آخر الملفات، الخطوط، النشاط الشهري، أنواع الملفات، وحالة المزامنة بين المحلي وGitHub (ملفات موجودة في مصدر دون الآخر).
- المشاهد يرى خطوطه فقط. تاريخ السفينة يؤخذ من اسم الملف/المجلد (YYYY-MM-DD) وإلا من تاريخ التعديل.
- ارفع إلى GitHub: `index.html` و`dashboard.js` و`dashboard.css` مع ملفات الواجهة السابقة. فهرس GitHub يتحدّث من نافذة الأرشيف (بناء الفهرس) عند المدير.
